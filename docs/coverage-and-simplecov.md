# Coverage, SimpleCov, and Ruby source checksums

## Runtime evidence

Test selection needs to know which Ruby files executed inside a test boundary.
MRI's [Coverage API](https://docs.ruby-lang.org/en/4.0/Coverage.html) is the
smallest standard primitive for this. Testmon snapshots cumulative line counters
around each serial test with `Coverage.peek_result` and records files whose
counters increased. It never clears counters between tests.

Coverage is process-global, so overlapping thread-parallel tests would make the
owner ambiguous. Testmon rejects Rails thread workers and native Minitest
`parallelize_me!`. Rails process workers instead record boundaries in each child
and send observations to the parent through validated spools.

TracePoint supplies complementary evidence for code compiled or loaded after
observers start, preloaded project methods, file operations, and child-thread
execution. Testmon propagates a revocable test token through Ruby's Thread
constructors; joined children keep exact ownership, leaked children revoke at
the boundary and reject publication, and unattributed pre-existing pools fail
closed as ambiguous. Targeted project line/call/block-call TracePoints avoid a
global Ruby callback over framework and gem code. C-backed methods generated by
project Ruby, such as `attr_accessor`, are indexed by owner and method name and
attributed from their native call event to the declaring source.

## Persisted checksum

Execution and change detection are separate concerns. Coverage and TracePoint
identify a Ruby source file used by a test. The persisted input checksum is
SHA-256 of that file's exact bytes.

Exact bytes are conservative: comments, whitespace, line endings, and encoding
bytes all cause the dependent test to run. That is intentional. It is simpler to
audit and cannot normalize away a meaningful change.

[`RubyVM::InstructionSequence`](https://docs.ruby-lang.org/en/4.0/RubyVM/InstructionSequence.html)
is implementation-specific and its binary/data formats are not stable. Testmon
uses instruction sequences only to check whether MRI can install the targeted
TracePoints needed for observation. ISeq bodies and compiler output are not
stored as dependency checksums.

## SimpleCov coexistence

SimpleCov is an application-facing coverage reporter, not the dependency store.
It remains responsible for filters, groups, thresholds, formatting, and merged
reports.

Keep its normal early setup:

```ruby
# test/test_helper.rb -- before requiring application code
require "simplecov"
SimpleCov.start "rails" do
  enable_coverage :branch
end

require_relative "../config/environment"
```

When Coverage is already running, Testmon reads it non-destructively with
`Coverage.peek_result`. It does not call `Coverage.result`, stop, clear, suspend,
resume, or restart the session. Coverage modes cannot be changed after startup,
so SimpleCov must remain the owner of its own early configuration. When Coverage
is not running, Testmon starts line/eval coverage for dependency observation.

SimpleCov reference: [SimpleCov README](https://github.com/simplecov-ruby/simplecov#readme).

## Why not a static source graph

Static indexing cannot prove that a particular test executed a dependency, and
Ruby/Rails dependencies also arise through metaprogramming, autoloading, dynamic
dispatch, templates, ordered lookup paths, I18n, fixtures, and file contents.
Conversely, a static reference can exist without running.

The KISS boundary is therefore:

- Coverage and targeted TracePoint identify executed Ruby files;
- exact-byte SHA-256 detects Ruby source changes;
- framework notifications and provider observers identify non-Ruby inputs;
- every inventory contributes a conservative suite-scoped membership checksum;
- incomplete attribution rejects publication.

Parsers and static indexes may improve diagnostics later, but they are not
selection evidence.
